# gene — браузерный ASCII-рогалик (MVP)

Пошаговый рогалик в духе DCSS: киборг из будущего в средневековом подземелье. Спецификация — `TZ.md`, журнал решений — `DECISIONS.md`.

## Требования

- Node.js 20+ (разрабатывается на 24 LTS)
- pnpm 10 (`npm i -g pnpm` или `corepack enable`)

## Запуск

```sh
pnpm install
pnpm dev        # сервер (порт 3000) + клиент Vite (http://localhost:5173)
```

Prod:

```sh
pnpm build      # проверка типов + сборка клиента и сервера
pnpm start      # http://localhost:3000 — сервер раздаёт собранный клиент
```

Порт сервера задаётся переменной `GENE_PORT`, путь к базе — `GENE_DB` (по умолчанию `packages/server/gene.db`),
каталог собранного клиента — `GENE_CLIENT_DIR` (по умолчанию `packages/client/dist`).

Docker:

```sh
docker build -t gene .
docker run -d -p 3000:3000 -v gene-data:/data gene   # http://localhost:3000, база — в томе /data
```

Для хостинга нужен постоянно работающий процесс (WebSocket) и постоянный диск под `/data`. Перед контейнером
ставится обратный прокси с HTTPS — клиент сам переключается на `wss://`.

## Как играть

Создай киборга (обозначение, формация тела, стартовое оружие), спустись на 3-й уровень и войди в портал `Ω`
(клавиша `>` на клетке портала). Портал охраняет орк-воин. Смерть окончательна; вкладку можно закрыть в любой момент —
партия продолжится с того же места.

| Клавиши | Действие |
|---|---|
| стрелки, numpad 1–9, `h j k l y u b n` | движение; атака — шаг в монстра; дверь открывается шагом |
| `.` / `5` / `s` | ждать ход |
| `R` | отдыхать, пока не восстановится здоровье (если врагов не видно) |
| `o` | автоисследование: идти к неизвестному, пока не встретится что-то новое |
| Shift + направление | бег по прямой до препятствия или чего-то нового |
| `g` / `,` | подобрать всё с клетки |
| `i` | инвентарь: буква — выбор предмета, `1`–`4` — надеть/снять, применить, выбросить, разобрать |
| `e` | экипировка: цифра — слот, буква — предмет, `-` — снять |
| `a` / `q` | применить (бинт → выбор органической части тела; ремкомплект → предмет или бионическая часть) |
| `d` | выбросить |
| `D` | разобрать (предмет уничтожается, ядро получает данные о типе) |
| `m` | база знаний ядра: навыки и изученность типов снаряжения |
| `x` | осмотр: курсор стрелками; или просто наведи мышь на клетку |
| `>` / `<` | лестница вниз / вверх, вход в портал |
| `?` | подсказка; `Esc` — закрыть окно |

**Символы:** `@` ты · `#` стена · `.` пол · `+`/`'` дверь · `<` `>` лестницы · `Ω` портал ·
`)` оружие · `[` броня · `!` зелье лечения · `?` бинт (белый) и ремкомплект (голубой) ·
`r` крыса · `j` шакал · `g` гоблин · `w` волк · `O` орк-воин.

**Тело киборга:** в диагностике `[Б]` — бионика (не регенерирует, чинится ремкомплектом), `[О]` — органика
(регенерирует, лечится бинтом и зельем). Искалеченная органика сама не заживёт выше «раны» без бинта.

## Тесты

```sh
pnpm test       # Vitest по всем пакетам
pnpm lint
```

Что покрыто автоматически (раздел 10 ТЗ): детерминизм; снапшот + лог = непрерывная игра; распределение попаданий по
весам; влияние ран по тегам (одинаково для игрока и монстра, четырёхрукий); смерть от `vital`-части и от общего HP;
прочность (износ только у брони поражённого слота, кривая эффективности, ремонт); материалы тела; изучение
(навык + тип, разборка, отсутствие точных чисел в `PlayerView`); победа через портал; сообщения (все монстры × части ×
типы урона × исходы, контрольные падежи и род); сервер (невалидная команда, невидимые монстры, вытеснение вкладки,
перезапуск сервера с переподключением по токену через настоящий WebSocket).

Вручную проверяется только визуальная часть: `pnpm dev`, пройти уровни в браузере.

## Шаблоны сообщений

Тексты боя и системных сообщений — в `packages/data/src/messages.ts` (`TEMPLATES`), код подстановки — в `packages/messages`.

**Ключи** ищутся от точного к общему: `hit.<семейство>.<тип урона>.<тяжесть>.<материал>` → `hit.<семейство>.<тип урона>.<тяжесть>` → … → `hit`.
Семейства атак: `weapon`, `bite`, `claws`, `fist`; типы урона: `slash`, `pierce`, `blunt`; тяжесть: `light`, `medium`, `heavy`.
Для каждого ключа — список вариантов, вариант выбирается детерминированно (сид партии + ход).

**Плейсхолдеры:**

| Запись | Значение |
|---|---|
| `{role.case}` | словоформа роли в падеже `nom/gen/dat/acc/ins/prep` |
| `{^role.case}` | то же с заглавной буквы |
| `{verb:ключ}` | глагол из `VERBS`, согласованный с подлежащим события: «ты бьёшь» / «гоблин бьёт» / «перчатки ломаются» |
| `{verb:ключ@role}` | глагол, согласованный с указанной ролью |
| `{adj:ключ@role}` | краткое прилагательное/причастие из `ADJECTIVES` по роду роли: «искалечен/искалечена/искалечено/искалечены» |
| `{label}`, `{pct}`, `{eff}`, `{skill}`, `{level}`, `{list}`, `{count}`, … | переменные конкретного события |

**Роли:** `attacker`, `target`, `victim`, `creature` — существа (игрок — «ты»); `part` — часть тела, `tpart` — она же с
владельцем («твою левую руку» / «левую руку гоблина»); `weapon` / `aweapon` — оружие или естественная атака (с владельцем-атакующим:
«твоей булавы» / «когтей волка»); `armour` / `tarmour` — броня цели; `item` / `oitem` — предмет (с владельцем).

Пример: `"{attacker.nom} {verb:бить} {target.acc} по {part.dat} {weapon.ins}."` → «Гоблин бьёт тебя по левой руке кинжалом.»

Сообщения ядра и диагностики начинаются с `[ЯДРО]`, `[ДИАГНОСТИКА]`, `[РЕМОНТ]` и выводятся как системные (другим цветом).

## Структура

```
packages/
  core/      игровая логика: чистый TS, без сети/БД/DOM/таймеров/Math.random
    src/combat/formulas/   ЗАГЛУШКА: все числа боя, ран, прочности, регенерации, опыта
    src/time/              ЗАГЛУШКА: очередь ходов и стоимость действий
  data/      данные: планы тел, монстры, предметы, навыки, словоформы, шаблоны сообщений
  messages/  ЗАГЛУШКА с каркасом: события core → русский текст
  server/    Node: WebSocket, сессии, SQLite (снапшот каждые 50 команд + лог команд), запуск core
  client/    Vite + Vue 3: карта на canvas, HUD, модальные окна, ввод
```

Главный интерфейс логики: `applyCommand(state, cmd) → { state, events }` (`packages/core/src/game.ts`).
Состояние — JSON-объект с ГПСЧ внутри; одинаковые `state` + `cmd` дают одинаковый результат. Сервер авторитетный:
клиент шлёт команды и получает `PlayerView` (только видимое и запомненное) и готовые строки лога.
